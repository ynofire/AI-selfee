# 프롬프트 템플릿 v1 사전 테스트

날짜: 2026-11-02 · 대상: `src/data/prompt.v1.md` + `buildExportMarkdown`

## 한계 (먼저 읽기)

- 이 테스트는 **같은 모델이 같은 세션 안에서** 프롬프트를 읽고 직접 결과를 써 본 것이다. 프롬프트를 처음 보는 AI의 반응이 아니다.
- 입력은 문항 11개짜리 **픽스처 은행**이라 실제 은행(140문항)보다 정보가 훨씬 적다. "정보가 적을 때 지어내지 않는가"를 보는 데는 오히려 맞지만, 실제 품질은 보장하지 않는다.
- 그래서 이 문서는 "프롬프트 구조가 깨지지 않는다"는 확인이다. **진짜 검증은 Task 12의 실사용**(민준이 자기 AI에 붙여 넣기)에서 한다.

## 입력 (픽스처 답변으로 만든 패킷, 입력 1~4 부분)

```
# 입력 1. 리포트 요약
- 표현 필터: 38/100 (생각을 그대로 말한다 ↔ 상대에 따라 가려서 말한다), 상대별 차이 측정 안 됨, 근거 80%, 신뢰도 타인 확인 · 타인 평가 75/100 (차이 37) · 상대별 차이 확인: 맞다
- 결정 방식: 80/100 (바로 정한다 ↔ 충분히 따져 본다), 상대별 차이 측정 안 됨, 근거 100%, 신뢰도 자기 보고

# 입력 2. 본인 답변 (축별)
## 표현 필터
- 불편한 얘기를 들었을 때 나는 → 말을 고른 뒤에 꺼낸다 [stated · 자기 보고]
- 처음 만난 사람에게 나는 → 있는 그대로 보여 준다 [stated · 자기 보고]
- 최근 한 달 동안 속마음을 숨기고 웃은 적은 → 1~2번 [stated · 행동 기반]
- (배우자) 배우자에게 서운한 일이 생기면 → 그날 바로 말한다 [stated · 행동 기반]
## 결정 방식
- (3개 문항, 모두 신중한 쪽 선택)

# 입력 3. 되고 싶은 나 ([desired])
- 1년 뒤의 나는 → 많이 달라졌으면 좋겠다 [desired]

# 입력 4. 지인 평가 ([other:호칭])
- [other:와이프] 표현 필터: 관찰 평균 4/5 (0~100 환산 75), 상대별 차이 확인: 맞다
```

## 기대한 출력과 실제로 쓴 결과 요약

프롬프트 규칙대로 쓰면 이런 결과가 나와야 한다.

- 머리말 `sources: [form]`, "읽는 법"은 memory_v0.4와 같은 태그 4종에 `[desired]`를 더한 형태.
- 1 core_facts, 8 scenes, 8b tastes, 9 time_axis: 설문이 수집하지 않으므로 **"(근거 부족)"**.
- 4 expression_filter: 아래 정도만 쓴다.
  - 불편한 얘기는 말을 고른 뒤 꺼낸다 [stated]
  - 배우자에게는 서운한 일을 그날 바로 말한다 [stated, 행동 기반]
  - 자기 점수 38 대 와이프 관찰 75, 차이 37 → 둘 다 적고 합치지 않는다 [stated] [other:와이프]
  - 와이프가 "상대에 따라 달라진다"에 동의함 → 상대별로 다르다는 점만 적고, **어떻게 다른지는 모른다** (측정 안 됨)
- 2 values_reasoning: 결정은 충분히 알아본 뒤 정한다, 표로 비교한다, 정보가 모일 때까지 둔다 [stated]. "세 문항이 같은 방향" → [observed]로 표시하고 어느 문항인지 적는다.
- 11 desired: "1년 뒤의 나는 많이 달라졌으면 좋겠다 [desired]" 한 줄. 어떻게 달라지길 원하는지는 쓰지 않는다.
- 10 to_verify: 표현 필터의 자기 38 대 타인 75 차이, 상대별로 어떻게 다른지, "많이 달라지고 싶다"의 방향.

### memory_v0.4와 구조 비교

- 대응: 읽는 법, 1~10, 8b, 11(desired 추가). 섹션 이름과 순서가 같다.
- 의도적 차이: 부록 A(project_notes), 부록 B(evaluation_log)는 클론 설계용 메모라서 설문 패킷에서는 요청하지 않는다.
- 태그 의미 차이: memory_v0.4의 `[observed]`는 "대화 중 Claude가 관찰함"이다. 설문 패킷에서는 대화가 없으므로 "여러 문항에서 같은 방향으로 반복된 패턴"으로 다시 정의했다. 그대로 두면 AI가 있지도 않은 대화를 관찰했다고 쓸 위험이 있다.
- 내용 차이: memory_v0.4는 인터뷰라서 사례와 말투가 풍부하다. 설문 패킷은 축 단위 위치와 선택지뿐이라 **memory.md가 훨씬 얇게 나온다**. 이건 설계상 한계이고, 사용자에게 "이 결과는 뼈대이고 살은 대화로 채워야 한다"고 알려야 한다 (Task 8 ExportScreen 안내 문구에 반영).

## 이 테스트로 찾은 것

1. **수정함**: 상대별 차이를 못 쟀을 때 패킷이 "상대별 차이 없음"이라고 썼다. AI가 "상대에 따라 달라지지 않는다"로 읽을 수 있어서 "측정 안 됨"으로 바꿨다 (`exportPackage.test.ts`에 RED→GREEN 테스트 추가).
2. **열어 둠**: 프롬프트는 AI가 출력에 설명 문장을 덧붙이지 못하게 막지 않는다("문서 하나만 출력"이라고만 썼다). 실사용에서 서두가 붙는지 Task 12에서 본다.
3. **열어 둠**: 리포트 줄의 "신뢰도 타인 확인 · 타인 평가 …"는 읽기에 조금 어색하다. AI가 오해할 정도는 아니라고 판단해 두었다.
