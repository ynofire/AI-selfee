# 배포 체크리스트

앱은 정적 사이트다. 서버도 DB도 없고, 답변은 사용자 브라우저(localStorage)에만 남는다.
빌드 결과(`dist/`)와 `vercel.json`이 배포의 전부다.

- 배포: https://selfee-ai.vercel.app (Vercel Hobby, `main` 기준).
- 단위·화면 테스트 165개 통과, `npm run build` 통과, 종단 테스트(`npm run e2e`) 통과.

## 배포 확인 결과 (2026-11-02, https://selfee-ai.vercel.app)

- 올라간 JS 번들(`index-DT9B7TLD.js`)이 로컬 `main` 빌드와 해시까지 같다.
- CSP 적용 확인: 운영 서버에서 일부러 보낸 `fetch`가 `connect-src 'none'`에 막혔다. 응답 헤더 문자열을 직접 읽지는 못했다.
- 세션 동안 나간 요청은 모두 같은 출처(HTML·JS·CSS)였다.
- `/r`, `/b`, 잘린 링크를 직접 열면 404가 아니라 앱의 "링크를 열 수 없어요" 화면이 나온다.
- 전체 흐름을 운영 서버에서 실행했다: 140문항(쉬어 가기 7번) → 리포트 15축 전부 점수, 유형 라벨·NaN 없음 → 내보내기 13,317자, 치환 안 된 `{{` 없음 → 초대 링크(해시 402자) → 지인 20문항 → 답장 링크(해시 234자) → v2 6축, `[other:와이프]` 줄 6개. 동의 전에는 저장 0건.
- 375px 폭에서 가로 스크롤 없음.
- 이 샌드박스는 `vercel.app`에 접근할 수 없어서 Playwright e2e(`BASE_URL=… npm run e2e`)는 돌리지 못했다. 같은 시나리오를 앱의 내장 브라우저에서 직접 실행했다. 로컬에서 `BASE_URL`을 쓰려면 이 컴퓨터에서 실행해야 한다.
- 아직 확인하지 못한 것: 카톡 안에서의 동작(`docs/kakao-check.md`), 응답 헤더 원문(`curl -sI`는 이 샌드박스에서 막힘).

## 1. GitHub 저장소

- 이름과 공개 여부는 네가 정한다. 저장소를 만들 때 README·.gitignore·라이선스는 추가하지 않는다 (빈 저장소).
- 코드에 비밀 값(API 키 등)은 없다. 앱이 외부 서비스를 부르지 않기 때문이다.
- 만들면 `owner/repo`를 알려준다. (완료: `ynofire/AI-selfee`)

## 2. 푸시 (내가 하지만, 네가 "푸시해"라고 하기 전에는 하지 않는다)

- 저장소를 세션에 붙이고 `main`과 `build/v1`을 올린다.
- 올리기 전에 `git log`와 올라갈 파일 목록을 보여준다.

## 3. Vercel 설정

Vercel에서 **Add New → Project → 그 저장소 Import**. 값은 이렇게 둔다.

| 항목 | 값 |
|------|----|
| Framework Preset | Vite |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | 기본값 |
| Environment Variables | 없음 |
| Web Analytics / Speed Insights | **끈다** (서버 쪽 방문 기록을 만들지 않기 위해) |

배포 브랜치는 `main`으로 한다. `vercel.json`이 `/r`, `/b` 경로를 `index.html`로 돌리고 보안 헤더를 붙인다. 따로 설정할 것은 없다.

## 4. 배포본 확인 (내가 함)

배포 주소를 받으면 두 가지를 돌린다.

```bash
# 응답 헤더: connect-src 'none' 이 있어야 한다
curl -sI https://<배포 주소>/ | grep -i content-security-policy

# 같은 시나리오를 배포본에 대해 실행 (서버를 띄우지 않고 CSP 헤더도 같이 확인)
BASE_URL=https://<배포 주소> npm run e2e
```

기대 결과:

- `Content-Security-Policy`에 `connect-src 'none'`이 있다.
- e2e가 통과한다 (140문항 → 리포트 → 내보내기 → 초대 링크 → 받는 사람 → 답장 링크 → v2 → 만료).
- 브라우저가 같은 출처 밖으로 보낸 요청이 0건이다.

참고: 로컬 `vite preview`는 `vercel.json`의 헤더를 적용하지 않는다. CSP는 배포본에서만 실제로 확인된다.

## 5. Vercel Hobby 조건

Hobby는 **비상업 용도만** 허용한다. 지금 구성은 해당 없음.

- 광고(AdSense 포함), 결제, 제휴 링크가 주목적인 구성은 안 된다.
- 제작·호스팅 대가를 받으면 안 된다.
- 후원 요청은 허용된다.

수익 모델을 붙일 때는 Pro로 옮기거나 호스팅을 바꾼다. 정적 사이트라 옮기는 비용은 작다.
출처: [Vercel Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines), [Vercel Hobby](https://vercel.com/docs/plans/hobby)

## 6. 개인정보처리방침 (네가 판단)

법률 자문이 아니고, 사실만 적는다. 이걸 보고 필요 여부를 정한다.

앱이 하는 것:
- 이메일, 전화번호, 이름 입력칸이 없다. 로그인이 없다.
- 답변은 사용자 브라우저에만 저장된다. 마지막 사용 후 7일이 지나면, 그 뒤 앱이 열릴 때 지워진다(서버가 없어서 앱이 열려야만 정리할 수 있다). "모두 지우기" 버튼이 있다.
- 동의 전에는 답변을 저장하지 않는다. (브라우저 저장소를 쓸 수 있는지 확인하려고 아주 짧게 임시 키 하나를 썼다가 바로 지운다.)
- 분석 도구, 광고, 외부 스크립트가 없다. CSP로 외부 연결을 막아 둔다.
- 링크 안의 내용(호칭, 축별 요약)은 `#` 뒤에 있어서 서버로 전송되지 않는다.

앱이 모르는 것 (호스팅 쪽):
- Vercel 같은 호스팅은 요청 기록(접속 IP, 시각, 경로 등)을 인프라 수준에서 남길 수 있다. 앱이 끌 수 있는 부분이 아니다.
- 이 기록을 개인정보로 볼지, 방침 문서가 필요한지는 서비스 범위(공개 여부, 이용자 수)에 따라 다르다.

확인할 곳: 개인정보 보호법과 [개인정보보호위원회](https://www.pipc.go.kr)의 안내, 필요하면 전문가.

## 7. 되돌리기

- 잘못 배포했을 때: Vercel의 Deployments에서 이전 배포를 Promote.
- 서비스를 내릴 때: Vercel 프로젝트를 삭제하면 사이트가 내려간다. 사용자 데이터는 서버에 없으므로 따로 지울 것이 없다.
