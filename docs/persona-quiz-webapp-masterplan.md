# 페르소나 문항 웹앱 (가칭) — 마스터 문서 v0.2

작성: 2026-11-02 · 상태: v0.2 승인됨 (2026-11-02). §5의 미결정 항목은 추천안을 기본값으로 채택했고, 이후 바꿀 수 있다.
상위 맥락: 디지털 클로닝(memory.md 만들기) 프로젝트의 "문항 → 인격" 단계를 앱으로 만드는 하위 프로젝트.

## 1. 한 줄 요약

구조화된 문항으로 사용자를 인터뷰하고, 결과를 (a) 화면 리포트와 (b) 사용자가 자기 AI에 붙여넣어 memory.md를 만들 수 있는 프롬프트 패키지로 내보내는 무료 웹앱. 사용자가 고른 지인(예: 와이프)은 링크로 리포트를 보고 약 20문항에 답해, 기본 인격 v2를 만든다.

## 2. 확정된 결정 (2026-11-02)

| 항목 | 결정 |
|---|---|
| 용도 | 제품. 모르는 사람도 쓴다. 무료로 운영한다 |
| 계정 | 로그인 없음. 이메일은 보낸 사람, 받는 사람 모두 수집하지 않는다 |
| 링크 전달 | 앱이 보내지 않는다. 사용자가 카톡 등으로 직접 전달한다 |
| 구조 | 서버·DB 없는 정적 사이트. 답변은 사용자 브라우저에만 저장한다. 처음 구상한 "서버 DB 7일 휘발"은 서버를 없애는 쪽으로 대체했다 |
| 리포트·인격 | 앱은 규칙 기반 리포트와 내보내기 파일까지만 만든다. 서술형 인격은 사용자가 자기 AI에서 만든다 (앱이 AI API를 호출하지 않는다) |
| 받는 사람 응답 | 보낸 사람에게는 축 단위 요약만 전달한다. 문항별 원답은 받는 사람 기기에만 남는다 |
| 호스팅 | Vercel Hobby (무료) |
| 후순위 | 재응답(재검사 일치도), 매일 심화 질문 |

호스팅 조건: Vercel Hobby는 상업 이용이 금지돼 있다. 광고(AdSense 포함), 결제, 제휴 링크가 주목적인 구성, 제작·호스팅 대가 수령이 있으면 안 된다. 후원 요청은 허용된다. 수익 모델을 붙일 때는 Pro로 옮기거나 호스팅을 바꾼다. 정적 사이트라 이전 비용은 작다.

## 3. 사용자 흐름 (승인됨)

보낸 사람: ① 시작·동의 → ② 문항 답변(15~20문항씩, 자동 저장, 민감 문항 건너뛰기) → ③ 리포트(축별 연속 점수, 상대별 차이, 근거 문항, 유형 라벨 없음) → ④ 내보내기(답변 전체 + 인격 생성 프롬프트, 복사·다운로드) → ⑤ 초대 링크 생성 → ⑥ 답장 링크를 열어 v2 리포트와 v2 내보내기를 받는다.

받는 사람: ① 안내·동의 화면(수집 항목, 보낸 사람에게 전달되는 범위, 건너뛰기·중단 자유) → ② 보낸 사람의 축 요약 열람 → ③ 약 20문항 → ④ 답장 링크 생성(축 단위 요약) → ⑤ 모두 지우기.

화면은 8~9개.

## 4. 설계 (승인됨)

### 4.1 데이터와 링크

- 보낸 사람 저장소: 브라우저 localStorage. 내용은 문항 은행 버전, 답변, 건너뛴 문항, 동의 기록, 마지막 활동 시각이다. 마지막 활동 후 7일이 지나면 화면에서 만료를 안내하고 삭제한다. 이 만료는 서버가 보증하는 것이 아니라 앱이 수행하는 것이다.
- 초대 링크: `/r#<payload>`. payload는 압축한 JSON이고, 호칭, 문항 은행 버전, 초대 식별자, 축별 요약(점수, 상대별 차이)을 담는다. 목표 길이는 1,000자 미만이다.
- 답장 링크: `/b#<payload>`. 받는 사람 호칭, 초대 식별자, 문항 은행 버전, 관찰 가능한 축마다 평가 평균 1개와 상대별 차이 확인 1개(축 단위 요약)를 담는다. 문항별 원답은 담지 않는다.
- `#` 뒤의 내용은 브라우저가 서버로 보내지 않는다. 앱에는 분석·추적 스크립트를 넣지 않는다.
- 링크는 서명되지 않는다. 링크 내용은 데이터로만 렌더링하고(HTML 삽입 금지), 스키마와 값 범위를 검증한 뒤 쓴다.
- 초대 링크를 받은 누구든 축 요약을 볼 수 있다 (비밀 토큰이 아니다). 보낸 사람에게 이를 고지한다.

### 4.2 리포트 계산

- 문항 형식: 양자택일(둘 다 좋은 선택지), 최근 한 달 행동 빈도, 같은 축의 상대별 반복, 최근 실제 사건 회상.
- 축 점수는 문항별 정규화 값의 가중 평균이다. 상대별 차이는 같은 축의 상대별 문항 간 분산이다.
- 항목마다 신뢰도 등급을 붙인다 (본인 보고 / 행동 기반 / 타인 확인). 받는 사람 평가가 들어온 항목은 `[other:호칭]`로 표시한다.
- 속마음 성격의 축은 본인 보고를 유지하고, 겉으로 보이는 축(말투, 상대별 반응, 책임·고마움 표현)에만 받는 사람 평가를 반영한다.
- 받는 사람 문항은 문항 은행의 raterItems(관찰자 관점 서술문)를 쓴다. 관찰 가능한 6개 축(표현 필터, 책임·역할, 임계점, 관계 유지, 고마움·사과·돌봄 표현, 말투·유머) × 3문항 + 상대별 차이 확인 2문항 = 20개다.
- 문항 은행은 앱과 분리된 데이터 파일(JSON)이다. 앱은 파일을 읽어 계산하므로 축·문항 수를 나중에 바꿔도 앱 수정이 거의 없다.

### 4.3 프롬프트 패키지

구성: ① 역할과 지시 ② memory.md 스키마 설명과 태그(`[stated]`, `[observed]`, `[other:]`, `[inferred]`, `[desired]`) ③ 답변 전체(문항, 선택, 상대, 신뢰도 등급) ④ 규칙(근거 없는 내용을 만들지 않는다, 근거가 약하면 비워 둔다, 겉으로 보이는 모습과 속마음을 구분한다). 앱을 만들기 전에 샘플 답변으로 실제 AI에 넣어 품질을 먼저 확인한다.

### 4.4 개인정보·동의·삭제

- 서버 전송 없음. "모두 지우기" 버튼 제공. 민감 문항은 건너뛸 수 있다.
- 받는 사람은 답하기 전에 무엇이 어떤 형태로 보낸 사람에게 가는지 첫 화면에서 본다.
- 내보내기를 AI에 붙여넣는 것은 사용자의 선택이고, 그 시점부터는 해당 AI 서비스의 처리 방침을 따른다는 것을 고지한다.
- 공개 전에 개인정보처리방침이 필요한지 확인한다 (법률 자문 아님, 별도 확인 필요).

### 4.5 테스트

- 링크 길이: 카톡이 요약이 담긴 링크를 자르거나 바꾸지 않는지 실측한다.
- 카톡 안에서 열리는 브라우저에서 진행 저장이 유지되는지 실측한다.
- 프롬프트 패키지를 실제 AI에 넣어 결과를 기존 memory.md(v0.4)와 비교한다.
- 만료 처리, 지우기, 잘못된 링크 입력(깨진 payload, 값 범위 초과)을 검증한다.
- 실사용: 민준 + 와이프 1회.

## 5. 미결정 / 확인 필요

1. 축 12개 그대로 갈지, 아래 3개를 더해 15개로 갈지: 스트레스·기분 반응, 새로움·위험에 대한 태도, 사람 만난 뒤의 에너지 소모. (결정: 15개 포함)
2. 문항 수: 재응답을 뒤로 미루면 첫 답변은 약 140개(인벤토리 120 + 극단 상황 20). 풀은 약 240. (결정: 첫 답변 140개로 시작)
3. 받는 사람의 약 20문항 내용: 축별 "이 리포트 문장이 맞는가"(5점)와 상대별 차이 확인 위주의 선택형을 제안한다. 자유 서술은 B 공개 범위(축 단위 요약만)와 충돌하므로 기본은 선택형만으로 한다. (결정: 선택형만)
4. 보낸 사람이 초대 링크에 포함할 축을 고를 수 있게 할지.
5. 서비스 이름과 도메인.
6. Cloudflare Pages 상업 이용 약관 확인 (호스팅 이전 시).

## 6. 비범위 (이번에 하지 않음)

이메일 발송, 로그인, 서버·DB, 앱 내 AI 호출, 결제·광고, 재응답 보정, 매일 심화 질문.

## 7. 검토했으나 채택하지 않은 방식

- Cloudflare Workers KV (정적 사이트 + 서버 저장 7일 만료): 자동 왕복은 편하지만, 무료 한도가 쓰기 1,000회/일이라 저장이 잦으면 하루 수십~백 명 수준에서 한도에 닿는다. 나중에 얹을 수 있게 링크 payload 형식을 동일하게 둔다.
- Supabase (Postgres): 무료 프로젝트는 1주 비활동 시 일시정지된다. 삭제 스케줄도 직접 구성해야 한다.
